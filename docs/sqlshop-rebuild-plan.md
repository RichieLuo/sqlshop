更新：2026-10-14，Asia/Shanghai。参考规则与证据见 `navicat-reference-spec.md`。

## 基线与约束

工作区已有大量未提交改动，保留并增量修改；不重置、不自动提交。保留 Rust、egui/eframe、数据库驱动、SSH、存储、SQLShop 品牌与图标。数据库操作仅使用 `.env.test` 与现有专用容器，凭据不写入文档或输出。

用户已明确选择直接读取二进制、反编译与静态资源复刻。Navicat 登录及原应用运行观察属于可选补充，不作为实施前置。下一批通过已有 ARM64 副本的真实方法实现、伪代码、调用关系与状态数据补充规格，再在 SQLShop 和专用测试库验收实现；静态推断与实际运行观察分别标明。

用户进一步授权：SQLShop 已有功能如果体验或实现质量逊于参考，可以重写和覆盖。保留已有未提交工作意味着不重置工作区，而不是冻结旧功能。以功能效果、操作成本、数据可靠性和可维护性评估替换；继续保留 SQLShop 品牌和三引擎、SSH、存储的有效能力，替换后的行为按实际测试验收。

## 功能清单（按重要性排序）

状态核对日期：2026-10-14。此前九项核心交互已收尾；本轮将原“未复刻”八组目标接成实际页面与后端：取消、恢复、事务、诊断、账号权限、比较同步、备份/调度/ER、引擎与认证扩展。表内逐项列出具体范围与剩余差异，不把基础流程写成原软件所有版本/选项完全一致。以工作区源码为准；新构建需要重启载入。同级按表中顺序排列，已实现功能不重复开发。

- **P0**：连接、查询、数据编辑与可靠性，是日常使用的基础。
- **P1**：高频对象管理与交互，优先补齐体验差距。
- **P2**：进阶管理、诊断与迁移。
- **P3**：扩展范围与发行。
- **实现状态**：已实现 = 表中明确的当前范围已有入口和后端；部分实现 = 有基础但关键环节缺失；未实现 = 没有专用功能入口和实现。能手写 SQL 完成某件事不等于有对应管理器。
- **复刻状态**：部分复刻 = 已按 N4/N6/N7 的静态资源或实际反编译链重建部分布局 / 核心流程；待核对 = 功能存在，但现有证据不足以确认与参考一致；未复刻 = 目标流程尚未建立。**已复刻核心流程** = 表内明确的交互范围已按证据接通，剩余功能 / 驱动差异仍单列；不据此称整项与原应用完全一致，也不按界面相似度估算百分比。H1 为原应用随包帮助，证据与范围见 `navicat-partial-rebuild-audit.md`。

此表是 SQLShop 的功能规划与现状清单；P2/P3 候选尚需核对参考二进制和用户需求，不表示本机 Navicat Lite 已确认启用全部候选功能。实现状态不代表本轮跑过完整测试、数据库 GUI 场景或跨平台验收。
