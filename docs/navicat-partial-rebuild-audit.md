## 按操作价值排序的改动

1. **现有行 inline 编辑**：移除普通格弹窗依赖，支持按 Tab / Enter 到相邻可编辑格，Escape撤销正在输入的值；提交按钮先同步编辑值。NULL与空串独立，原主键及快照不变。
2. **schema执行闭环 + 结果消息 / 错误定位**：源文档目标、选区起点和结构化错误穿过 worker 到 UI。仅补控件而不补执行目标会制造误操作。
3. **文档 identity与切换**：选SQL文件先 canonicalize并找已有普通SQL tab；命中则激活且保留dirty输入 / 结果 / 目标。另存为与已有文档路径冲突时保护已有输入。Command-{ / }切换应包含固定对象页。
4. **主窗口可配置布局**：View加入导航、信息、主工具栏、状态；专注模式隐藏辅助pane，同时保留菜单及恢复快捷入口。N4 `NSKeyEquiv=1/2`的modifier还需核对，不能只据字符就把准确快捷键断言成Command-1/2。
5. **树工具和搜索**：全部折叠先处理egui持久展开状态，下一帧保留收起；搜索只强制展开匹配祖先，并显示真实无结果反馈。无需自动连接所有服务器来完成搜索。
6. **信息栏常规 / DDL / 查询预览**：复用已读结构的DDL和SQL文稿，切页不触发隐式SQL执行；不存在元数据时给出读取入口。DDL查看与设计编辑文档仍分离。
7. **页 / 记录导航**：首页、页码输入、首 / 上 / 下 / 末当前页记录；保留页大小与草稿保护。尾页统计的性能、过滤参数化及读写权限应由后端能力决定。
8. **设计页字段查找**：按名称过滤 / 定位，保留当前选择和编辑输入，SQLServer/MySQL可排序范围别照抄成三引擎都能ALTER顺序。完整字段网格与DDL能力另追专用NIB / 保存代码。

## 必须明确的策略差异

`data_edit.html`说明原产品可在移动到另一条记录或关闭表时保存。SQLShop此前已明确选择**多格本地暂存、手动原子提交、关闭保护、冲突检查**。本批可复制网格输入与导航，但不能悄悄切换为过行自动数据库写入。N6的提交入口事实也不能证明SQLShop事务策略与原程序完全一致。

`data_rdbms.html`明确表单视图仅适用于 Premium/企业/标准版；不用把Form视图缺失自动列作Lite核心复刻阻塞。类似完整AI、ER、权限、流程功能需按本机Lite实际支持范围继续核对。
