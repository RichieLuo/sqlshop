## 查询标签与执行

Navicat：N7 确认每个查询控制器有 server/catalog/schema 控件及自身 `_serverInUse`、`_holderRef`。新查询在主浏览页或连接树有焦点时取树节点最近的 schema→catalog→server holder，否则取当前 `CCCoreUIFormInfo` 文档的 holder；目标变更会禁用依赖控件并异步装载 catalog/schema。运行时从本查询文档按 schema→启用的 catalog→server 选取有效目标，捕获到后台 operation，更新该文档 form 后调用 `runQuery`/`explainQuery`。全文/选区分别复制 SQL 后汇合到同一执行入口，空 SQL 返回、未选有效 server 时有提示。每文档 holder/server 仅证明目标模型，尚不证明独立网络 socket；当前语句的完整解析、错误位置、快捷键、取消与完整事务仍有未知，未宣称运行事实。

SQLShop 当前实现：每个 SQL 标签明确绑定连接和数据库，并持有独立查询连接。新查询继承当前对象工作区或活动文档的目标。改变查询下拉目标不会切换管理会话；已有查询会话改目标先确认结束原会话。选区只发送选区；当前语句按光标选择完整语句（Ctrl/⌘+Shift+Enter）；全文使用独立入口。语句边界跳过方言字符串、标识符和注释，无法可靠判定的批处理语法拒绝当前语句执行。写入确认保存 SQL、目标、标签会话版本及连接配置快照。运行中不能关闭或改绑该标签；已提供独立取消通道，服务器确认前保持执行保护。

## 表数据编辑：核心状态与完整流程

Navicat：已从真实实现追踪提交前同步编辑器、Grid/Form 分派、后台保存及主队列恢复交互；NULL 与空串有独立入口。表保存实际进入 libcc 的执行器；发现条件性开始事务调用，完整提交/回滚策略仍未解析。具体函数与局限见 `navicat-binary-findings.md`，不能依据菜单名推断自动提交或原子性。

SQLShop 自行选择的规则：

1. 表标签保存数据库快照与原始主键。仅有可用主键、支持的列类型及事务能力的普通表允许编辑；其他对象说明只读原因。
2. 单元格 NULL 是 `None`，空字符串是 `Some("")`。暂存新值覆盖网格显示并标记，数据库快照不被改写。修改主键后，其他字段仍使用原始主键定位；改回原值移除该项。
3. 多格暂存按行合并为 UPDATE；同一批次在事务中检查原值、提交或回滚。普通服务器冲突保留草稿，用户可以调整或丢弃。
4. 提交中冻结暂存快照，不允许再次编辑、丢弃、刷新、翻页、应用/重置筛选或关闭该标签。打开单元格编辑窗时先完成或取消当前编辑，再提交或丢弃整批。
5. 丢弃只撤销本地草稿，网格恢复快照；不是取消已经发送的数据库写入。切换标签保留草稿，关闭含草稿标签要求先处理。
6. 提交成功清除已提交草稿，标明数据库写入已成功，并重新读取当前页。刷新失败必须报告“已提交，刷新失败”，不能把提交标为失败，也不能允许基于旧快照继续写入。
7. 普通刷新先冻结旧快照；成功后替换，失败后保留旧数据显示并标记过期。重新成功读取前禁止编辑。
8. 断线后保留草稿。断线可能发生在服务器已提交之后；应进入“结果待核实”状态，允许恢复连接并读库核实，不能直接自动重试。此恢复状态机属于后续批次，当前尚未具备。
9. 复制和导出语义必须明确：结果复制/CSV 导出默认基于已读取的数据库结果；暂存新值尚未写入数据库。完整表导出读取数据库，不把本地草稿混入。

代码审查发现的提交期间撤销、网格暂存值显示、展开筛选、编辑窗提交与过期快照问题已修复；直接 NULL/空串、单格撤销与 F2/Enter 编辑也已实现。断线草稿现可保留、独立重连核实当前值并显式处理冲突，未知新增结果不自动重放。实施范围与验收见重建计划。

## 网格内新增记录

用户明确要求 ＋ 的作用是在表格底部追加可填写的行。SQLShop 已将原新增弹窗替换为独立新增草稿：支持多行直接填写，初始使用默认值，自增 / 生成 / 不支持编辑的列交给数据库；右键可指定默认值、NULL、文本空串或移除草稿行。＋追加后滚动至新行并定位首个可输入列，−对选中新草稿只作本地移除。空表与仅有生成列的普通表也可新增；无主键限制已有记录修改，不限制普通表新增。

新增行不写入 `ResultSet.rows` 或 `TableData.keys`，复制 / 导出仍使用数据库快照。提交全部捕获新增与已有修改，先验证并生成全部 SQL，再在同一事务内 UPDATE / INSERT；更新仍使用原主键和原值。普通 SQL 错误 / 冲突回滚整批并保留草稿，提交或连接结果不确定沿用断线与过期保护。撤销暂存同时清理新增和修改，草稿不持久保存。提交成功后刷新当前页，新记录可能因筛选 / 排序 / 分页不在当前页显示，状态明确保留成功提示。

此交互来自用户明确要求及 SQLShop 事务设计；现有二进制证据未确认原应用完整网格新增与混合保存策略。真实数据库 GUI 验收待后续，本批仅完成编译 / 静态检查和原生示例布局检查。

## 数据网格的筛选与排序入口

SQLShop 操作改进：表数据列头单击按升序 → 降序 → 清除循环，默认替换排序；Shift+单击追加 / 修改该列，多列排序保留优先级，右键可指定方向或移除此列排序。箭头与序号显示已应用排序，圆点显示已应用筛选。排序沿已有参数化分页读取在数据库执行并返回第一页，不在本地重排行或主键。

单元格右键将数据库快照中的值带入等于 / 不等于条件；文本支持包含，NULL 使用 IS NULL / IS NOT NULL，空串保留为空串。列头也可添加筛选条件。条件先进入当前表标签的草稿面板，检查后点击应用；工具条区分已应用与待应用。忙碌、编辑窗口、暂存修改、过期快照或目标不匹配时，网格入口禁止改变读取条件。普通 SQL 结果不显示这些服务端表操作。

N4/N6 支持表格编辑入口与保存链；现有静态证据尚未确认列头排序和单元格筛选的精确参考行为。本节是 SQLShop 自行选择的规则，不能标为原程序运行事实。

## 会话与事务

Navicat：同连接不同标签和数据库的隔离、自动提交、显式事务、取消和断开行为待验证。

SQLShop 当前每个连接配置有管理会话，每个 SQL 标签另有持久查询会话。同连接的多个 SQL 标签可并行；管理会话浏览切库不移动查询目标或结束其事务。临时表、变量和显式事务可跨该标签的多次执行保留。普通 SQL 错误保留会话，PostgreSQL 事务出错后仍可 ROLLBACK；传输错误或超时销毁源标签的查询会话，下次用户主动运行才建立新连接，当前 SQL 不自动重试。USE 成功或普通 SQL 错误后的实际数据库只回写源标签。重连、断开或删除配置会结束所属查询会话，忙碌时禁止；存活用户会话退出前确认。早期后端验证覆盖三引擎 TCP 和 SSH；本轮新增事务状态、操作控件与驱动取消仅完成编译和静态检查，不能推断未确认写入的提交结果。

SQLShop 当前结构在独立“表名 · 设计”文档中打开，同对象数据 / 设计各按角色复用标签。字段、索引、外键、DDL 用页内子标签切换，元数据可横向滚动 / 拖宽 / 选择；现有有限字段 / 索引修改以页内编辑区呈现，SQL 预览与确认也在设计文档内。各文档独立保存本次运行的输入、选择、预览和错误，不在标签切换时覆盖其他表。关闭 / 退出含输入的设计文档提示，刷新重新读取并保留输入、清理原预览。异步结果按来源 UUID 回填；结构修改成功清来源设计输入并标同对象数据页过期，失败保留输入并要求重新读取实际结构。视图结构可查看，普通表修改能力仍有限；PostgreSQL 删除列先检查依赖。N7 支持 identity / formRole 的文档模型，具体字段布局与页内确认来自用户明确交互要求和 SQLShop 设计，未宣称已恢复原应用像素布局或完整字段保存流程。

高级结构管理另批实现。DDL 的自动提交和锁影响遵循引擎行为。CSV 保留 NULL 与空串区别；导入先预览和检查类型/列映射，失败定位到输入行；完整导出不能只导出当前分页。现有三引擎数据验证持续复用。
